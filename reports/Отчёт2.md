## Использованные абстракции Kubernetes

### Namespace

Все ресурсы приложения размещаются в namespace `uptime-monitor`.

### ConfigMap

ConfigMap `uptime-monitor-config` хранит несекретные настройки приложения и PostgreSQL:

- `HTTP_PORT`
- `WORKER_COUNT`
- `JOB_QUEUE_CAPACITY`
- `SCHEDULER_INTERVAL`
- `DATABASE_PING_TIMEOUT`
- `SHUTDOWN_TIMEOUT`
- `POSTGRES_DB`
- `POSTGRES_USER`

### Secret

Secret `uptime-monitor-db` хранит чувствительные данные:

- `POSTGRES_PASSWORD`
- `DATABASE_URL`

`POSTGRES_PASSWORD` передаётся в контейнер PostgreSQL. `DATABASE_URL` передаётся в Job миграций и backend.

### StatefulSet

PostgreSQL запускается как `StatefulSet` с одной репликой. Для хранения данных используется `volumeClaimTemplates`. Kubernetes создаёт PersistentVolumeClaim с режимом доступа `ReadWriteOnce` и объёмом `1Gi`.

### Service PostgreSQL

Service с именем `postgres` предоставляет адрес для подключения к PostgreSQL:

```text
postgres:5432
```

Service выбирает Pod PostgreSQL по label `app: postgres` и перенаправляет запросы на его порт `5432`.

### Job миграций

Job `uptime-monitor-migrate` применяет миграции базы данных. Job использует тот же образ `uptime-monitor:local`, в котором находятся:

- бинарник backend;
- CLI `migrate`;
- каталог `/app/migrations`.

При запуске Job выполняется команда:

```bash
/app/migrate -path /app/migrations -database "$DATABASE_URL" up
```

При ошибке Kubernetes повторяет выполнение Job до `backoffLimit` раз.

### Deployment backend

Приложение запускается как Deployment `uptime-monitor` с одной репликой. Использует образ:

```text
uptime-monitor:local
```

### Service приложения

Приложение слушает порт `8080` внутри контейнера. Service использует внутренний порт `8080` и публикует приложение наружу через NodePort `30080`.

## Взаимодействие сервисов приложения

Сначала запускается PostgreSQL и подключается постоянное хранилище. После его готовности отдельный Job применяет миграции базы данных. Затем запускается backend-приложение.

Пользователь открывает frontend через Service приложения `uptime-monitor`. Service передаёт запрос Pod backend. Backend обращается к PostgreSQL через Service `postgres:5432`, а база сохраняет данные в подключённом хранилище.

```text
Пользователь
    ↓
Service приложения
    ↓
Backend
    ↓
Service postgres
    ↓
PostgreSQL
```
